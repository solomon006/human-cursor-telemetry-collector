# MotorCursor

## Описание проекта

**MotorCursor** — это исследовательское приложение на движке Godot, предназначенное для высокоточного сбора телеметрии движения курсора мыши. 

Цель проекта — собрать качественный, богатый метаданными датасет человеческих движений мышью. В дальнейшем эти данные будут использованы для обучения ML-моделей, способных реалистично имитировать движения курсора (например, для тестирования интерфейсов, анализа UX или генерации человекоподобного ввода).

В отличие от существующих открытых датасетов (которые часто создаются для систем анти-фрода и обхода капч), этот проект является частью **научной работы** и фокусируется на полноте данных. Открытые датасеты часто упускают критически важные переменные, влияющие на биомеханику движения, такие как:
- Размер и положение стартовой и целевой зон.
- Физические параметры пользователя (правша/левша, возрастная группа).
- Аппаратное обеспечение (игровая мышь vs офисная, параметры экрана).
- Состояние "фокуса" (отвлечение, выход за пределы окна и т.д.).

MotorCursor решает эту проблему, фиксируя не только сырые координаты, но и точную геометрию задачи, условия сессии и фазы движения.

## Как это работает?

Пользователю предлагается серия заданий (trials) в формате "point-and-click" (наведи и кликни). 
1. Приложение фиксирует текущую позицию курсора как стартовую точку попытки.
2. Появляется целевая кнопка на расстоянии и под углом из воспроизводимого `trial_plan.json`.
3. Пользователь должен как можно точнее и естественнее переместить курсор и кликнуть по цели.
4. Приложение записывает события ввода с микросекундной точностью, геометрию задачи, тайминги, фазы движения и quality-флаги.

## Натуралистический сбор данных

Помимо контролируемых point-and-click заданий, MotorCursor включает фазу **натуралистического сбора данных**. После завершения основного эксперимента участнику предлагается заполнить стилизованную веб-форму (имитация реальной формы регистрации с полями ввода, капчей и чекбоксами). 

Цель этой фазы — собрать движения курсора в контексте, приближенном к реальному использованию интернета. Это позволяет обучать ML-модели на разнообразных паттернах движения: не только прямолинейные перемещения к целям фиксированного размера, но и навигация по интерфейсу, заполнение форм, взаимодействие с чекбоксами и кнопками.

## Архитектура данных

Проект использует многоуровневую архитектуру сохранения данных для обеспечения надежности и удобства последующего анализа:

1. **Raw Sessions (`raw_sessions/*.jsonl`)**: Сырой, линейный поток всех событий во время записи. Обеспечивает максимальную безопасность данных — если при парсинге произойдет ошибка, исходные логи всегда можно восстановить.
2. **Структурированные таблицы (JSONL)**: Разделение данных на логические сущности (участники, сессии, попытки, события ввода).
3. **Производные признаки (`derived_features.parquet`)**: Рассчитанные после сбора метрики (кинематика, время реакции и т.д.), готовые для загрузки в Pandas/Polars и обучения моделей.

Полное описание схемы данных и всех собираемых полей можно найти в файле [docs/data_schema.md](docs/data_schema.md).

## Разработка (Godot)

Приложение строится на базе Godot 4.x. 
Ключевые архитектурные принципы:
- **Координатная система**: Viewport pixels.
- **Время**: Микросекунды (через `Time.get_ticks_usec()`).
- **События ввода**: Перехват сырых событий (не просто чтение позиции в `_process`), чтобы избежать потери данных между кадрами.
- **Старт попытки**: текущая позиция курсора в момент появления цели.
- **План эксперимента**: условия берутся из `trial_plan.json` и перемешиваются по фиксированному seed.

## Нормализация данных

После сбора raw-логов можно собрать аналитические таблицы:

```bash
python3 tools/normalize_raw_sessions.py /path/to/raw_sessions -o dataset
```

На выходе создаются `participants.jsonl`, `sessions.jsonl`, `trials.jsonl`, `input_events.jsonl` и дополнительные таблицы событий качества/блоков.
